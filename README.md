# bb_risk_dashboard
もちろんです。謝る必要はありません。バックテストは最初は分かりにくくて当然です。
このアプリは、次の順番で使えば大丈夫です。

①銘柄を入力 → ②現在の条件を確認 → ③損切りを先に決める → ④利確候補を確認 → ⑤過去データで検証

なお、こちらではリアルタイム相場を取得できません。アプリの価格も外部データのため、遅延や欠損の可能性があります。実際の最新価格・注文条件はmoomooで確認してください。

1．最初の設定方法
画面左側のサイドバーを設定します。最初は、ほとんどを初期値のまま使って構いません。

項目	初心者向けの意味
銘柄コード	調べたい銘柄を入力
データ期間	過去何年分を確認するか
時間足	1本のローソク足が何日分か
BB期間	ボリンジャーバンドの計算期間
BB標準偏差	バンドの広さ
ATR期間	値動きの大きさを測る期間
直近安値の確認本数	損切り候補を探す範囲
BB下限接近許容幅	BB下限にどこまで近づけば接近とするか
条件成立点数	エントリー候補として表示する最低点
銘柄コードの例
日本株：7974.T
米国株： AAPL.US
米国株： GOOG.US
最初に使いやすい設定
設定に慣れるまでは、次の初期値を変えずに操作してみてください。

データ期間：5y
時間足：1d
BB期間：20
BB標準偏差：2.0
ATR期間：14
直近安値：10本
BB下限接近許容幅：1.0％
条件成立点数：7.0点
設定を頻繁に変えると、どの条件が結果に影響したのか分かりにくくなります。最初は同じ設定で複数の銘柄や期間を観察する方が理解しやすくなります。

2．「現在の条件」の見方
最初のタブでは、現在のローソク足がBB下限反発の条件を満たしているか確認します。

4種類の判定
待機
BB下限付近ではありません。

意味：今はこのアプリの監視条件に該当していない
「上がりそうだから追いかける」という意味ではなく、単にBB下限反発型の条件が成立していない状態です。

落下中・監視
BB下限付近まで下がっていますが、反発が確認されていません。

BB下限に到達
　　↓
しかし陽線反転や下限回復がない
　　↓
まだ落下中の可能性
このアプリで最も重要な表示です。BB下限に触れただけでは底打ちとは判断しません。

弱い反発
反発らしい値動きはありますが、RSIやMACDなどの補助条件が不足しています。

条件成立候補
設定した数式上の条件が成立しています。

ただし、これは「買えば上がる」という表示ではありません。

買い指示ではない
将来の上昇保証ではない
条件を満たしたことを知らせる表示
条件表の意味
確認項目	簡単な意味
BB下限付近に到達	株価が下限バンドに近づいた
反発を確認	下落後に戻す動きが出た
下限割れから回復	終値がBB下限の上へ戻った
陽線反転	終値が始値を上回った
RSIが改善	下落の勢いが少し弱まった
MACDが改善	モメンタムが前の足より改善した
200日線以上	長期的な価格位置を確認
出来高が平均以上	通常より売買が増えた
BB下限が急落していない	下限に沿う急落を警戒
点数は、複数の条件を見やすくまとめたものです。点数だけで判断せず、「反発を確認」が成立しているかを一緒に見るのが基本です。

3．「計画と保有管理」の使い方
この画面では、先に損切り価格を決め、その後に1:1.5と1:2の利確候補を計算します。

手順1：エントリー価格を入力
「予定または実際のエントリー価格」に価格を入力します。

まだ保有していない場合：確認用の予定価格
すでに保有している場合：実際の平均取得価格
外部データの終値と実際の約定価格が異なる場合は、実際の価格を手動入力してください。

手順2：損切り計算方法を選ぶ
ATR基準
最近の値動きの大きさを使って損切り価格を計算します。

値動きが大きい銘柄 → 損切り幅が広くなりやすい
値動きが小さい銘柄 → 損切り幅が狭くなりやすい
直近安値基準
最近の安値を割った位置に損切り候補を置きます。

考え方は「この安値を割ったら、想定した反発が崩れた可能性がある」です。

ATRと直近安値の遠い方
ATR基準と直近安値基準を比較し、より低い損切り価格を使います。損切り幅が広がりやすい点に注意が必要です。

手動入力
自分で決めた損切り価格を入力します。学習段階では、自動計算との違いを確認する用途にも使えます。

「1R」とは何か
ロングの場合、エントリー価格から損切り価格までの差を1Rと呼びます。

例として、仮に次の計画だったとします。

エントリー価格：1,000
損切り価格：950
この場合は、

1R ＝ 1,000 − 950
   ＝ 50
となります。

利確候補は次の計算です。

1:1.5目標 ＝ 1,000 ＋ 50 × 1.5
           ＝ 1,075
1:2目標   ＝ 1,000 ＋ 50 × 2
           ＝ 1,100
この価格は「必ず到達する目標」ではありません。最初に想定した価格差を可視化するための水準です。

エントリー後の管理
「確認時の価格」と「エントリー後の最高値」を入力すると、現在何R進んでいるか表示されます。

現在R	意味
マイナスR	エントリー価格を下回っている
0R～1R	利益方向だが、まだ1R未満
1R以上	当初リスクと同じ幅だけ上昇
1.5R以上	1:1.5の価格帯へ到達
2R以上	1:2の価格帯へ到達
「参考管理ストップ」は学習用の自動計算です。実際の注文価格や約定状況と一致するとは限りません。

特に、含み損が出た後に損切り価格を引き下げると、当初の1Rが拡大します。

損切りを下げる
　　↓
最大損失の想定が大きくなる
　　↓
最初のリスクリワード計算が崩れる
4．バックテストとは何か
バックテストとは、現在のルールを過去の値動きに当てはめたら、どのような結果になったかを機械的に調べる作業です。

天気予報に例えると、次のような確認です。

「この雲が出た翌日は雨」と決める
　　　　↓
過去5年間の天気で試す
　　　　↓
何回雨が降り、何回外れたか調べる
このアプリでは、次の流れを過去データ上で繰り返します。

① BB下限付近に到達
② 反発条件と点数条件が成立
③ 次の足の始値で入ったと仮定
④ 損切り価格と利確価格を計算
⑤ どちらへ先に到達したか確認
⑥ 結果をRで記録
実際の操作
「③ 過去データ検証」タブを開き、最初は初期設定のまま使います。

検証時の損切り方法を選ぶ
ATR倍率を確認する
最大保有本数を確認する
スリッページを確認する
「1:1.5と1:2を検証する」を押す
最大保有本数
利確にも損切りにも到達しなかった場合、何本目まで保有したと仮定するかです。

日足で40本なら、おおむね40営業日分です。週足で40本なら40週間分なので、時間足によって意味が変わります。

スリッページ
表示された価格と実際の約定価格のずれを再現するための設定です。

例えば急落時には、損切り価格を設定していても、その価格で必ず約定するとは限りません。バックテストでは、売買時に少し不利な価格を使って試算します。

売買コスト
売買に伴うコストを仮定する欄です。実際の手数料体系や諸費用は取引条件によって異なるため、moomooの最新情報をご確認ください。

このアプリの保守的な処理
日足だけでは、「その日に利確と損切りのどちらへ先に触れたか」が分からない場合があります。

そのため、同じローソク足の中で両方へ到達していた場合は、保守的に損切りを先に記録します。

また、始値が損切り価格を下回っていた場合は「ギャップ損切り」とし、損切り価格ではなく始値付近で決済したものとして扱います。

5．バックテスト結果の読み方
バックテストでは、勝率だけを見ないことが大切です。

項目	初心者向けの意味
取引回数	過去に条件が何回出たか
勝率	利益になった取引の割合
平均R	1回当たりの平均結果
中央値R	極端な結果の影響を抑えた中心値
利益係数	利益合計と損失合計の関係
累積R	全取引の結果Rを合計したもの
最大ドローダウンR	過去の山から最も大きく落ち込んだ幅
取引回数
取引回数が非常に少ない場合、良い結果でも偶然の可能性があります。

取引回数が少ない
　　↓
1回の大きな利益や損失に左右されやすい
　　↓
結果を断定しない
勝率
勝率が高いから安全、低いから使えない、とは限りません。

例えば、1回の利益が比較的大きく、1回の損失が小さい方式では、勝率が低くても平均Rがプラスになる場合があります。反対に、勝率が高くても一度の損失が大きければ、累積結果が悪化する場合があります。

平均R
平均Rは、1回の取引で平均して何Rになったかを示します。

平均Rがプラス：過去の設定上は利益側
平均Rがマイナス：過去の設定上は損失側
ただし、プラスでも将来の結果を保証しません。

最大ドローダウンR
連続損失や成績悪化の大きさを表します。

累積Rがプラスでも、途中で大きな落ち込みがあることがあります。一般的な投資家や市場参加者は、最終結果だけでなく、この途中経過も確認できます。

1:1.5と1:2の比較
この2つは、優劣を決めるための表示ではありません。

1:1.5は利確価格が比較的近い
1:2は利確価格が比較的遠い
利確価格が変わると、保有期間や次に使われるシグナルも変わる
そのため、2つの売買履歴は完全に同一にはならない
「勝率」「平均R」「最大ドローダウンR」「取引回数」「決済理由」をセットで観察してください。

初心者向けの毎回の確認表
□ 銘柄コードは正しいか
□ データ最終日は古くないか
□ BB下限に触れただけで判断していないか
□ 反発確認は成立しているか
□ エントリーより先に損切り候補を確認したか
□ 1Rの価格差を理解したか
□ 1:1.5と1:2を「到達保証」と考えていないか
□ バックテストの取引回数は十分か
□ 勝率だけでなく平均Rと最大ドローダウンも見たか
□ 実際の最新価格をmoomooで確認したか
まずは実際の売買判断に直結させず、過去のチャートを見ながら、なぜ「落下中」「弱い反発」「条件成立候補」になったのかを確認する学習用として使うと理解しやすくなります。

本内容とアプリは一般的な学習・検証用であり、個別の売買判断を示すものではありません。バックテストは過去の一定条件による試算で、将来の成果や実際の約定を保証しません。
